# v0.7.0 — Retry/Cancel Fix, AI Gateway Client Improvements

## Summary

Fixes critical bugs in the job retry and cancel views that prevented them from communicating with the AI Gateway. The retry view was calling a non-existent endpoint with a wrong payload, and the cancel view was missing authentication headers. Adds a `resume_job` method to the AI Gateway client.

## All Changes

### Bug Fixes

- `fix(jobs)`: **Retry view** — was calling wrong AI Gateway URL (`/v1/api/jobs/start` instead of `/jobs/run`), sending wrong payload (missing `download_url`, extra `organization_id`), and missing `X-API-Secret-Key` auth header. Refactored to delegate to the Celery task `process_drone_imagery` which already handles presigned URL generation and uses the correct `AIGatewayClient`.
- `fix(jobs)`: **Cancel view** — was calling AI Gateway without `X-API-Secret-Key` auth header. Refactored to use `AIGatewayClient.cancel_job()` which includes proper authentication.
- `fix(processings)`: Legacy `AIServiceAdapter.start_job()` URL corrected from `/jobs/start` to `/jobs/run`.

### Improvements

- `feat(jobs)`: Added `AIGatewayClient.resume_job(job_id, stage)` method for the AI Gateway `POST /jobs/{job_id}/resume` endpoint.
- `refactor(jobs)`: Retry view no longer uses `httpx.AsyncClient` with `asyncio.new_event_loop()`. Uses the existing Celery task pipeline instead, eliminating code duplication.
- `refactor(jobs)`: Cancel view no longer manually constructs HTTP requests. Uses `AIGatewayClient` consistently.

### Files Changed

|------|---------|
