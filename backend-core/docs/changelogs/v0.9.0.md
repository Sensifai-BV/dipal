# v0.9.0 — KPI Metrics Endpoint

## Summary

Adds a new unauthenticated `GET /metrics/` endpoint designed for CloudWatch dashboard scraping. Exposes uptime, processing throughput, job status breakdown, average processing and queue wait times, and authentication failure counters. All security metrics are stored in Redis with hourly bucketing and 90-day retention.

## All Changes

### Features

- `feat(metrics)`: New `MetricsView` at `GET /metrics/` — unauthenticated endpoint for CloudWatch ingestion.
  - **Uptime**: `uptime_seconds`, `started_at`, `version`, `celery_workers` count.
  - **Processing**: `total_jobs`, `by_status` breakdown (pending, processing, completed, failed, cancelled), `avg_processing_seconds`, `avg_queue_wait_seconds`.
  - **Throughput**: `completed_last_1h`, `completed_last_24h`, `per_hour_24h`.
  - **Failure tracking**: `failed_last_24h` count.
- `feat(metrics)`: New `record_auth_failure()` function — stores login failure counts in Redis with hourly buckets (`photogear:backend:auth_failures:YYYYMMDDHH`), 90-day TTL.
- `feat(security)`: Security metrics in `/metrics/` response — `auth_failures_1h`, `auth_failures_24h`, `auth_failures_total` (from Redis).
- `feat(auth)`: `AccountLoginUserAPIView` now calls `record_auth_failure()` on every failed login attempt.

### Infrastructure

- `feat(urls)`: Registered `/metrics/` route in `config/urls.py` alongside existing `/health/`.
- `feat(version)`: Bumped `_SERVICE_VERSION` to `0.9.0` in `health.py` and `metrics.py`.
