# v0.10.3 — Celery Task Terminal Status Guard

## Summary

Prevents stale Celery tasks from re-dispatching already-cancelled, completed, or failed jobs to the AI Gateway. When a job is cancelled via the API but the Celery task is still queued in the broker, the worker would previously overwrite the status back to `PROCESSING` and dispatch to AI — causing cancelled jobs to resume processing. The task now checks the job's current status before proceeding and silently returns if the job is in a terminal state.

## All Changes

### Bug Fixes

- `fix(tasks)`: Add terminal status guard to `process_drone_imagery` Celery task. After fetching the job from the database, the task now checks if `job.status` is `CANCELLED`, `COMPLETED`, or `FAILED` and returns early without dispatching to AI Gateway. This prevents stale broker tasks from overwriting terminal statuses back to `PROCESSING`.

### Tests

- `test(tasks)`: Add 3 tests to `TestProcessDroneImageryTask`: `test_task_skips_cancelled_job`, `test_task_skips_completed_job`, `test_task_skips_failed_job`. Each creates a job in a terminal state, runs the Celery task, and asserts the status is unchanged and the AI client was never called.
