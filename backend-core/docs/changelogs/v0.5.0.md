# v0.5.0 — Job Timing, Upload Failure Handling, Duration Fix

## Summary

Fixes critical production issues found during live AI pipeline testing: job API now exposes `started_at`/`completed_at` timestamps, duration calculation uses correct fields instead of `updated_at - created_at`, and upload failures are properly reported back to mark jobs as failed instead of silently succeeding.

## All Changes

### Bug Fixes

- `fix(jobs)`: Duration calculation used `updated_at - created_at` which always showed ~1 second. Now uses `started_at`/`completed_at` with fallbacks in both list and detail views.
- `fix(jobs)`: Variable name collision (`end` used for both pagination and duration) caused `TypeError` in job list view.
- `fix(jobs)`: Detail view crashed with `TypeError` when `completed_at` was `None` for completed jobs (missing fallback guard).

### Features

- `feat(jobs)`: Added `started_at` and `completed_at` fields to `ProcessingJobListSerializer` and both job list/detail API responses.
- `feat(jobs)`: New `upload_status` callback type in `AICallbackView` — AI Gateway sends upload results after background product uploads complete.
- `feat(jobs)`: `_handle_upload_status` marks jobs as FAILED when any product uploads fail, with descriptive error messages listing failed product types.

### Infrastructure

- `test(jobs)`: Added 2 tests for `upload_status` callback (all-success and with-failures scenarios).
- `test(jobs)`: Added 4 tests for `started_at`/`completed_at` presence and correct duration in list and detail views.
- Updated OpenAPI schemas for list and detail views to include new timestamp and duration fields.
