# v0.4.0 — RBAC, Security Hardening, Integration & Load Tests

## Summary

Major security release implementing Role-Based Access Control (RBAC), fixing a
critical permission bug, protecting all AI service endpoints, enforcing
cross-organization data isolation, and adding comprehensive test coverage for
security (44 tests), integration (30+ tests), and load/performance (24 tests).
Total backend test count grows from 328 to 389.

---

## All Changes

### Bug Fixes

- **fix(permissions):** Fix `IsSystemAdminOrOwner` — was comparing FK object to
  string (`request.user.role == 'owner'`), always evaluated False. Now uses
  `getattr(request.user.role, 'name', None)` with `RoleName` enum.
- **fix(uploads):** `DatasetListView` returned all datasets when user had no
  `org_id`. Now returns HTTP 400 requiring organization membership.

### Features

- **feat(rbac):** Create `RoleName(TextChoices)` enum in `accounts/models/role.py`
  with `ADMIN` and `USER` values. All role string literals replaced with enum
  references across 7+ files.
- **feat(rbac):** Create centralized permission classes in `utils/permissions.py`:
  `IsAdmin` (role or superuser check), `IsOrganizationOwner` (object-level org
  match), `IsAIService` (validates `X-API-Secret-Key` header).
- **feat(rbac):** Auto-assign admin role on user creation via
  `CustomUserManager.create_user()` when no role is provided.
- **feat(security):** Protect all AI service endpoints with `IsAIService`
  permission: `StartProcessingView`, `JobListView`, `AICallbackView`,
  `ProductUploadInitView`, `ProductChunkUploadView`,
  `ProductUploadCompleteView`, `ProductUploadAbortView`.
- **feat(tests):** Add 44 security/RBAC tests covering permission classes,
  protected endpoint auth enforcement, cross-org isolation, AI secret key
  validation, default admin role assignment, and no-org user restrictions.
- **feat(tests):** Add 30+ integration tests covering registration-to-API flow,
  dataset CRUD lifecycle, job lifecycle with callbacks, job management
  (list/filter/cancel/retry/rerun), product flow, pagination, dashboard stats,
  and full pipeline simulation.
- **feat(tests):** Add 24 load/performance tests covering concurrent
  registration (15 simultaneous), concurrent authentication (10 simultaneous),
  concurrent dataset/job operations (10 users), cross-org isolation under load,
  API response time thresholds, database scaling with 100+ records, rapid-fire
  sequential requests (50 iterations), and mixed read/write workloads.

### Infrastructure

- **refactor(permissions):** Remove redundant manual `_verify_secret_key()` calls
  from product upload views — now handled by `IsAIService` permission class.
- **refactor(models):** Add `choices=RoleName.choices` to `Role.name` field for
  database-level validation.

### Breaking Changes

- AI service endpoints (`/jobs/start-job/`, `/jobs/ai-callback/`,
  `/products/upload/*`) now require `X-API-Secret-Key` header via `IsAIService`
  permission class. Previously some had empty `permission_classes = []`.
- `DatasetListView` now returns HTTP 400 if user has no organization. Previously
  returned all datasets (data leak).
