# v0.8.0 — Request ID Tracing, Retry Cancelled Jobs

## Summary

Enables end-to-end request tracing using chromatrace's `RequestIdMiddleware`. The frontend's `X-Request-ID` header is captured by Django middleware and forwarded to AI Gateway calls, so all logs across services share the same trace ID. Also allows retrying cancelled jobs.

## All Changes

### Features

- `feat(middleware)`: Added `chromatrace.django.RequestIdMiddleware` to Django `MIDDLEWARE`. Reads `X-Request-ID` from incoming requests and sets it in chromatrace's context variable, so all logs within that request include the trace ID prefix `[R-xxxxxxxx]`.
- `feat(jobs)`: AI Gateway client (`_get_headers()`) now forwards `X-Request-ID` from the current trace context to all outbound requests (job submission, status polling, cancel, resume).
- `feat(uploads)`: Legacy AI service client (`trigger_ai_processing`) now forwards `X-Request-ID` to outbound requests.
- `feat(jobs)`: Retry now allowed for both `failed` and `cancelled` jobs (was `failed` only).

### Files Changed

| File | Changes |
|------|---------|
| `config/settings.py` | Added `chromatrace.django.RequestIdMiddleware` to `MIDDLEWARE` |
| `apps/jobs/infra/services/ai_client.py` | Import `trace_id_ctx`, forward `X-Request-ID` in `_get_headers()` |
| `apps/uploads/domain/aiservices.py` | Import `trace_id_ctx`, forward `X-Request-ID` in `trigger_ai_processing()` |
| `apps/jobs/api/views/job_retry_view.py` | Allow retry for `CANCELLED` status |
