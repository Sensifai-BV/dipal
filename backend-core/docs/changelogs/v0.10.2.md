# v0.10.2 — Deprecate radiometric_calibration Parameter

## Summary

Makes the `radiometric_calibration` request parameter optional when starting a processing job. When omitted, the value is automatically derived from `analysis_mode`: `true` for `"full"` mode, `false` for `"fast"` mode. This reflects the reality that the AI pipeline auto-detects multispectral images from metadata and ignores the flag entirely — making `analysis_mode` the single source of truth for processing intent. The field remains in the job list serializer response for backward compatibility.

## All Changes

### Refactoring

- `refactor(serializer)`: Made `radiometric_calibration` optional (`required=False, default=None`) in `StartProcessingRequestSerializer`. Clients that omit the field get the value derived from `analysis_mode`.
- `refactor(views)`: `StartProcessingView.post()` now derives `radiometric_calibration` from `analysis_mode == "full"` when the field is not provided. Added `AnalysisMode` import.
- `feat(serializer)`: Added `radiometric_calibration` and `analysis_mode` to `ProcessingJobListSerializer.Meta.fields`, exposing both in the job list API response (`GET /api/jobs/`).

### Files Changed

| File | Changes |
|------|---------|
| `apps/jobs/api/serializer.py` | `radiometric_calibration` optional in request serializer; added to list serializer fields |
| `apps/jobs/api/views/views.py` | Derive `radiometric_calibration` from `analysis_mode` when omitted; import `AnalysisMode` |
