# v0.10.1 — Healthcheck S3 Resilience

## Summary

Fixes the `/health/` endpoint causing container restarts when S3 is unreachable. S3 failures now degrade the health status instead of marking the service unhealthy, a 3-second timeout prevents the check from hanging, and the correct S3-prefixed credential environment variables are now used.

## All Changes

### Bug Fixes

- `fix(health)`: S3 check failure now sets overall status to `"degraded"` (HTTP 200) instead of `"unhealthy"` (HTTP 503). This prevents Docker/ECS from restarting the container when S3 is temporarily unreachable.
- `fix(health)`: Added `BotoConfig(connect_timeout=3, read_timeout=3, retries={"max_attempts": 0})` to the S3 boto3 client. Previously, `head_bucket()` could hang for ~60 seconds on network issues, causing the health check to exceed Docker's timeout and trigger a container kill.
- `fix(health)`: Fixed S3 credential environment variable names from `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` to `AWS_S3_ACCESS_KEY_ID` / `AWS_S3_SECRET_ACCESS_KEY`, matching the actual env vars set in deployment.
