# v0.3.0 — Health Check, URL Upload Fix, Job Duration, FMIS Webhooks

## Summary

Major reliability release adding a health check endpoint, fixing critical bugs
in the URL upload flow (5 bugs including a broken S3 method call), adding
accurate job duration tracking via dedicated `started_at`/`completed_at` fields,
hardening FMIS webhook task error handling, and completing the `.env.example`
with missing variables. Includes 35 new unit tests.

---

## All Changes

### Bug Fixes

- **fix(uploads):** Replace non-existent `copy_from_external_s3()` call with
  `copy_from_presigned_url()` in `urluploadtasks.py`. This was the root cause
  of all URL upload failures.
- **fix(uploads):** Remove duplicate `org_id` assignment in
  `UploadFromUrlView` — was overwriting `organization_id` from user with a
  second lookup.
- **fix(uploads):** Fix `KeyError` on `data['batch_id']` — replaced with
  `data.get('batch_id')` and UUID fallback.
- **fix(uploads):** Fix `KeyError` on `data['file_name']` — replaced with
  `data.get('file_name')` and URL-derived fallback.
- **fix(uploads):** Remove unused `src_access_key`/`src_secret_key` parameters
  from `download_and_process_url_task` call.
- **fix(jobs):** Job duration was incorrect because `auto_now` on `updated_at`
  is not triggered when using `save(update_fields=[...])`. Added explicit
  `started_at` and `completed_at` DateTimeField columns.
- **fix(jobs):** AI callback `_handle_completion` and `_handle_error` now set
  `completed_at = timezone.now()` explicitly.
- **fix(jobs):** Task runner now sets `started_at = timezone.now()` when
  processing begins.
- **fix(jobs):** `get_duration()` serializer method now uses
  `started_at`/`completed_at` with proper fallbacks.
- **fix(fmis):** Initialize `job = None` before try block in
  `process_job_task` to prevent `UnboundLocalError` if `Job.objects.get()`
  raises.
- **fix(fmis):** Add separate `Job.DoesNotExist` exception handler in
  `process_job_task` for clearer error reporting.
- **fix(fmis):** Fix wrong import `from infrastructure.logging` →
  `from config.logging_config` in FMIS tasks.
- **fix(config):** Correct `.env.example` variable names:
  `JWT_ACCESS_TOKEN_LIFETIME_DAYS` → `ACCESS_TOKEN_EXPIRE_MINUTES`,
  `JWT_REFRESH_TOKEN_LIFETIME_DAYS` → `REFRESH_TOKEN_EXPIRE_DAYS`.
- **fix(config):** Make Redis port configurable via `REDIS_PORT` env var
  instead of hardcoding `6379` in channel layers.

### Features

- **feat(health):** Add `/health/` endpoint returning JSON with service status,
  version, uptime, and dependency checks (database, Redis, Celery).
  Returns 200 for healthy/degraded, 503 for unhealthy. No authentication
  required.
- **feat(config):** Add missing env vars to `.env.example`: `JWT_SECRET_KEY`,
  `JWT_ALGORITHM`, `REDIS_HOST`, `REDIS_PORT`, `REDIS_DB`,
  `CORS_ALLOW_ALL_ORIGINS`, `DATASET_IMAGE_EXTENSIONS` (commented),
  `DATASET_METADATA_EXTENSIONS` (commented).

### Infrastructure

- **ci(jobs):** Migration `0006_add_started_at_completed_at` — adds
  `started_at` and `completed_at` nullable DateTimeField columns to
  `ProcessingJob`.
- **ci(products):** Migration `0004_alter_product_type` — updates Product type
  choices.
- **refactor(uploads):** Replace `print()` calls with structured logger in
  `urluploadtasks.py`.
- **refactor(fmis):** Add structured logging to all FMIS task functions.

### Breaking Changes

No changes.
