# v1.3.0 — Switch Retry to Rerun Endpoint

## Summary

Updates the processing job retry flow to use the backend's consolidated `/rerun/` endpoint instead of the now-removed `/retry/` endpoint. The retry UI remains unchanged — "Continue from Last Step" and "Restart from Beginning" — but the underlying API call now targets `/rerun/` with the `resume` query parameter.

## All Changes

### Features

- `feat(processing-jobs)`: Route changed from `/retry/` to `/rerun/` — aligns with backend v0.10.0 endpoint consolidation.
- `feat(processing-jobs)`: `retryJob()` service function now sends `resume` param (inverted from old `force_restart`): "Continue from Last Step" → `resume=true`, "Restart from Beginning" → `resume=false`.

### Files Changed

| File | Changes |
|------|---------|
| `src/module/processing-job/service/processing-jobs.route.ts` | `retry` key renamed to `rerun`, URL changed to `/rerun/` |
| `src/module/processing-job/service/processing-jobs.service.ts` | `retryJob()` now calls `rerun` route with `resume: !forceRestart` param |

## 🔙 Backend Changelog

| Change | Impact | Action Required |
|--------|--------|-----------------|
| Frontend now calls `POST /api/jobs/{job_id}/rerun/?resume=true\|false` | Backend v0.10.0 required — the `/retry/` endpoint no longer exists | **Required** — deploy backend v0.10.0 before this frontend version |
