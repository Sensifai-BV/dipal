# v1.3.1 — Product Viewer & Download Fixes

## Summary

Fixes three product-related issues: (1) non-raster products (band manifest, calibration outputs) downloaded with the wrong `.ply` extension instead of their actual format, (2) DSM/DEM products rendered as a near-uniform color blob in the TIF viewer because GDAL nodata values (e.g. `-9999`) were included in the min/max normalization, and (3) TIF viewer errors were silently swallowed, leaving an infinite loading spinner.

## All Changes

### Bug Fixes

- `fix(products)`: Product download now extracts the file extension from the S3 URI (`item.uri`) instead of using a hardcoded binary ternary (`"tif"` or `"ply"`). This fixes band manifests downloading as `.ply` instead of `.json`, and calibration products downloading with incorrect extensions.
- `fix(tif-viewer)`: TIF viewer now reads the `GDAL_NODATA` metadata tag from GeoTIFF files and excludes nodata pixels from the min/max range calculation. DSM/DEM files with nodata values (e.g. `-9999`, `-10000`) now render with the full viridis colormap across the actual elevation range. Nodata pixels are rendered as transparent.
- `fix(tif-viewer)`: Added `try/catch` around the entire `loadTiff()` function. Errors (corrupted files, unsupported compression, memory issues) now display a red error message instead of leaving an infinite loading spinner.

### Files Changed

| File | Changes |
|------|---------|
| `src/module/products/pages/products/products.vue` | `downloadProduct()` extracts extension from `item.uri` with fallback |
| `src/core/components/others/three-viewer/tif-viewer.vue` | GDAL nodata handling, `bandMinMax()` skips nodata values, error overlay, `try/catch` in `loadTiff()` |
