# v1.3.4 — Products Page Job-Awareness & Band Product Tracking

**Date:** 2026-05-03

The Products page now knows whether the associated job is still running and
responds accordingly: an in-progress banner replaces the misleading
"X expected products not available" amber alert while the pipeline is active.
Five per-band orthomosaic products are also added to the expected-products
list so they are tracked once the job completes.

Previously, the amber "missing products" alert appeared immediately while
processing was still underway — users had no visual indication that products
were simply not uploaded yet, and band ortho ZIPs (`band_green`, `band_red`,
`band_red_edge`, `band_nir`, `band_blue`) were never checked at all even
after job completion.

---

## All Changes

### Features

- `feat(products)`: Add `ACTIVE_JOB_STATUSES` constant (`Set<string>`) containing
  `"pending"`, `"queued"`, and `"processing"` — the three states where products
  are legitimately absent.
- `feat(products)`: Add `STAGE_LABELS` constant (`Record<string, string>`) mapping
  pipeline stage keys (`radiometric_calibration`, `sfm`, `orthomosaic_generation`,
  `uploading`, `publishing`) to human-readable labels for display in the banner.
- `feat(products)`: Extend `EXPECTED_PRODUCTS` with five band ortho entries:
  - `band_green` — Green Band Ortho (ZIP)
  - `band_red` — Red Band Ortho (ZIP)
  - `band_red_edge` — Red Edge Band Ortho (ZIP)
  - `band_nir` — NIR Band Ortho (ZIP)
  - `band_blue` — Blue Band Ortho (ZIP)

### Bug Fixes

- `fix(products)`: Amber "not available" alert is now gated on `!isJobActive`.
  It only shows when the job is in a terminal state (`completed`, `failed`,
  `cancelled`) and products are genuinely missing.
- `fix(products)`: Add blue in-progress banner (`v-if="isJobActive"`) that shows
  a spinner, the current stage label from `STAGE_LABELS`, and numeric progress
  percentage while the job is running.  Populated from `getJobDetail` response
  fields `status`, `stage`, and `progress`.

### Files Changed
