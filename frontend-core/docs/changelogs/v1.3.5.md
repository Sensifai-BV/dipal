# v1.3.5 — Job Failure Banner & Live Status Polling

**Date:** 2026-05-03

The Products page now polls the job status while processing is active and
displays an explicit red error banner when the job has failed.  Band ortho
product labels no longer incorrectly say "(ZIP)".

Previously, the page fetched job detail once on mount and never refreshed it.
If the job failed after the initial load, the failure was never surfaced — the
in-progress banner from v1.3.4 continued showing indefinitely.  Additionally,
band ortho entries in `EXPECTED_PRODUCTS` carried "(ZIP)" suffixes that were
left over from when band outputs were packaged as ZIP archives; they are now
uploaded as plain GeoTIFFs.

---

## All Changes

### Bug Fixes

- `fix(products)`: Add a 5-second polling loop (`setInterval`) that runs while
  `isJobActive` is `true`.  When the job transitions to a terminal state the
  polling stops (`clearInterval`), products are re-fetched, and the UI updates
  accordingly.  The interval is also cleared in `onUnmounted` to prevent leaks.

- `fix(products)`: Add a red "Job failed" banner (`v-if="jobStatus === 'failed'"`)
  with a `CircleX` icon and a short message directing users to retry from the
  Jobs list.

- `fix(products)`: Gate the amber "missing products" alert on
  `jobStatus !== 'failed'` in addition to `!isJobActive` — the alert no longer
  appears when the job has failed (the red banner takes its place).

- `fix(products)`: Remove "(ZIP)" suffix from all five band ortho labels in
  `EXPECTED_PRODUCTS`.  Labels are now plain:
  - `band_green` — "Green Band Ortho"
  - `band_red` — "Red Band Ortho"
  - `band_red_edge` — "Red Edge Band Ortho"
  - `band_nir` — "NIR Band Ortho"
  - `band_blue` — "Blue Band Ortho"
