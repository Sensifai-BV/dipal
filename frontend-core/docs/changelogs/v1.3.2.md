# v1.3.2 — Missing Products Banner & Multispectral Detection

## Summary

Improves the missing products banner on the Products page to distinguish between genuinely missing core products (which may indicate a failed job) and multispectral products that are simply unavailable because the dataset contains only RGB images. The page now fetches the job detail to read `analysis_mode` from the API instead of relying on a heuristic, and the `radiometric_calibration` parameter is no longer sent when creating processing jobs — the backend derives it from `analysis_mode`.

## All Changes

### Features

- `feat(products)`: Split the missing products alert into two distinct sections:
  - **Core products** (orthomosaic, DSM, etc.) — amber warning suggesting to retry the processing job.
  - **Multispectral products** (NDVI, NDRE, GNDVI, calibrated reflectance) — neutral gray info banner explaining the dataset does not contain multispectral images.
- `feat(products)`: Added `getJobDetail()` service function and route to fetch individual job details from `GET /api/jobs/{job_id}/`.
- `feat(products)`: Products page now reads `analysis_mode` from the job detail API to determine multispectral status, replacing the previous heuristic approach.
- `feat(products)`: Added `MULTISPECTRAL_PRODUCT_TYPES` constant listing the four multispectral product types.

### Refactoring

- `refactor(processing-config)`: Removed `radiometric_calibration` from `processingConfig` — no longer sent when starting a job. The backend now derives it from `analysis_mode`.
