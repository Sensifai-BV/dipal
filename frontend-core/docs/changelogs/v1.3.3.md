# v1.3.3 — Error Display Overhaul

## Summary

Fixes the broken error toast system that was dumping raw JSON response objects to users, showing duplicate error toasts, and auto-dismissing errors after only 2 seconds. Errors now display clean, human-readable messages in a single toast that stays visible for 8 seconds.

## All Changes

### Bug Fixes

- `fix(axios)`: Rewrote the Axios response interceptor to extract a human-readable error message from API responses instead of passing the raw Axios response object as the toast message. The new `extractErrorMessage()` function checks `data.error`, `data.detail`, and `data.message` fields in order, with user-friendly fallbacks for network errors, timeouts, and HTTP status codes (403, 404, 500+).
- `fix(axios)`: 401 responses now silently redirect to login without showing an error toast.
- `fix(axios)`: The interceptor sets `error._toastShown = true` so downstream catch blocks can avoid duplicate toasts.
- `fix(toast)`: Increased error toast auto-dismiss duration from 2 seconds to 8 seconds, giving users enough time to read error messages.
- `fix(processing-config)`: Processing configuration `startProcessing()` catch block now skips toast if interceptor already showed one.
- `fix(processing-job)`: Retry, cancel, and delete job handlers now skip toast if interceptor already showed one.
- `fix(data-set)`: Delete dataset, retry import, and export handlers now skip toast if interceptor already showed one.
- `fix(configuration)`: Webhook save and delete handlers now skip toast if interceptor already showed one.
- `fix(auth)`: Login and registration error handlers now skip toast if interceptor already showed one.
- `fix(data-set-service)`: S3 upload error handler now skips toast if interceptor already showed one.
