# v0.8.0 — Pipeline Benchmarking Suite

## Summary

Adds a comprehensive benchmarking system for the AI image processing pipeline.
The suite is executable via `python -m benchmark` with full argparser CLI,
supports dataset presets for the East Kazakhstan (Zenodo) and WUR (Dataverse)
reference datasets, and produces structured JSON reports with accuracy
validation, timing metrics, and visual quality assessment.

---

## All Changes

### Features

- `feat(benchmark)`: Add `BenchmarkSettings` pydantic model with `BENCHMARK_`
  env prefix — configures dataset path, GPU count, number of runs, timeout,
  gateway URL, target GSD, and five validation thresholds (checkpoint RMSE H/V,
  radiometric R², reproducibility, GSD accuracy).
- `feat(benchmark)`: Add `BaseRunner` abstract class with automatic timing
  wrapper, exception handling, and `run_multiple()` for reproducibility testing.
- `feat(benchmark)`: Add `CalibrationRunner`, `SFMRunner`, `OrthoRunner` —
  stage-specific runners that call services via the API gateway and save
  per-run results to JSON.
- `feat(benchmark)`: Add `PipelineRunner` orchestrator that runs configured
  stages in order (calibration → SFM → orthomosaic) with progress output.
- `feat(benchmark)`: Add `CheckpointValidator` — computes horizontal and
  vertical RMSE against surveyed ground control points (ASPRS standard).
- `feat(benchmark)`: Add `RadiometricValidator` — computes per-band and overall
  R² coefficient of determination against reference reflectance measurements.
- `feat(benchmark)`: Add `SpatialValidator` — measures GSD accuracy from
  orthomosaic metadata/GeoTIFF and pixel-wise reproducibility correlation
  across multiple runs.
- `feat(benchmark)`: Add `VisualQAValidator` — detects coverage gaps, blur,
  color inconsistency, and seam artifacts using OpenCV (lazy-imported).
- `feat(benchmark)`: Add `ReportGenerator` — produces timestamped JSON reports
  with per-stage timing summaries, validation results, and overall pass/fail
  verdict. Prints human-readable summary to stdout.
- `feat(benchmark)`: Add argparser CLI (`python -m benchmark`) with 20+ flags
  including `--dataset-path`, `--gpu-count`, `--num-runs`, `--stages`,
  `--validate`, `--target-gsd`, and all threshold overrides.
- `feat(benchmark)`: Add dataset presets (`--dataset zenodo-eastkazakhstan`,
  `--dataset wur-dataverse`) that auto-configure stages, GSD, and sensor type.
- `feat(benchmark)`: Add `--list-datasets` to list all available presets.
- `feat(benchmark)`: Add `--detect-layout` to scan a dataset directory and
  print detected images, ground truth files, reference products, and sensors.
- `feat(benchmark)`: Add `detect_dataset_layout()` utility that auto-discovers
  image directories, GCP files, reference products, and sensor hints.

### Infrastructure

- `infra(config)`: Add `BENCHMARK_*` environment variables section to
  `.env.example` (dataset path, GPU count, thresholds, gateway URL).

### Tests

- `test(benchmark)`: Add 31 unit tests covering `BenchmarkSettings`,
  `BaseRunner`, `CheckpointValidator`, `RadiometricValidator`,
  `ReportGenerator`, CLI parser, `args_to_settings`, dataset presets
  (`get_preset`, `list_presets`, `detect_dataset_layout`), and preset
  application logic.

## Benchmark Report Metrics

The following metrics are provided in the benchmark report when `--validate` is used:

| Metric | Validator | Report Field | Threshold |
|--------|-----------|-------------|-----------|
| Horizontal positional accuracy | `CheckpointValidator` | `horizontal_rmse` | < 0.10 m |
| Vertical positional accuracy | `CheckpointValidator` | `vertical_rmse` | < 0.15 m |
| Radiometric accuracy (R²) | `RadiometricValidator` | `r_squared` + `band_results` | > 0.85 |
| Reproducibility | `SpatialValidator` | `reproducibility_correlation` | > 0.99 |
| GSD fidelity | `SpatialValidator` | `gsd_measured`, `gsd_deviation` | within 5% |
| Visual QA score | `VisualQAValidator` | `score`, `artifacts_detected` | > 0.70 |

Performance metrics (per stage, per run):
- `elapsed_seconds` — wall-clock time
- `success` / `error` — pass/fail status
- `min_time_seconds`, `max_time_seconds`, `mean_time_seconds` — stage summaries
- `success_rate` — fraction of successful runs
