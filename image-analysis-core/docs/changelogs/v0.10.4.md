# v0.10.4 — Geo-registration: Geotagged Orthomosaic & DSM Outputs

**Date:** 2026-04-26

Fixes the missing geotag issue on all generated outputs (orthomosaics and 3D maps). The COLMAP sparse model was previously reconstructed in an arbitrary local coordinate system with no real-world CRS attached, even though GPS EXIF priors are present in the input images. This release adds a `geo_register` step to the SFM pipeline that runs `colmap model_aligner --alignment_type gps` immediately after bundle adjustment, aligns the model to ECEF, and writes a `geo_reference.json` sidecar file. The orthomosaic service reads that sidecar and applies a `filters.reprojection` (ECEF → UTM) plus `override_srs` in the PDAL pipeline, so all output GeoTIFFs are correctly georeferenced. Multispectral band orthorectifications and vegetation indices inherit the CRS from the DSM, so they are also geotagged without further changes.

## All Changes

### Bug Fixes

- `fix(sfm)`: Add `geo_register()` step to the SFM pipeline between `bundle_reconstruction` and `undistort`. Runs `colmap model_aligner --alignment_type gps` to transform the sparse model from its arbitrary local frame to ECEF (WGS84, EPSG:4978). Saves `geo_reference.json` in the SFM run directory containing `centroid_lat`, `centroid_lon`, `utm_epsg`, and `input_srs`. Without this step, COLMAP outputs have no real-world coordinate system despite reading GPS EXIF priors.
- `fix(orthomosaic)`: Update `generate_dsm_from_pointcloud` in `OrthomosaicService` to read `geo_reference.json` and insert a `filters.reprojection` (ECEF → UTM) stage plus `override_srs` into the PDAL pipeline. DSM GeoTIFFs now carry the correct UTM CRS and geotransform. When no sidecar is found (legacy datasets), the previous behaviour is preserved with a warning log.
- `fix(orthomosaic)`: Update `generate_rgb_orthomosaic` in `OrthomosaicService` to apply the same ECEF → UTM `filters.reprojection` + `override_srs` pattern per RGB band. Previously, PDAL attempted to rasterise ECEF-coordinate points (~4,000,000 m magnitude) at 1 cm/px resolution, producing a uniform gray output with no valid pixel data. Each R/G/B per-band PDAL pipeline now reprojects to UTM before rasterising, restoring correct pixel colours and embedding the UTM CRS in the output GeoTIFF.
- `fix(orthomosaic)`: Replace `_median_composite_band` in `ms_orthorectification.py` with a GPS-guided warping pipeline (`_gps_composite_band`). Previously, each calibrated reflectance image (which covers ~1/N of the field) was naively resized to the full DSM pixel dimensions and blended by median — this produced pronounced horizontal banding artifacts matching the drone's flight strips. The new approach: (1) looks up each image's original source file from `band_manifest`, (2) extracts GPS lat/lon/alt from EXIF, (3) computes ground footprint from altitude + default 65° HFOV, (4) assigns a WGS84 geotransform, (5) runs `gdalwarp` to project to the target UTM grid, then (6) merges all warped images with `gdal_merge` using nodata-aware averaging. Falls back to the legacy approach when `band_manifest` is not available.

### Features

- `feat(sfm)`: Add `geo_register` abstract method to `IService` interface and implement it in `ColmapService`. Two module-level helpers are added: `_extract_gps_from_images` (reads GPS EXIF via Pillow from all images in the input directory) and `_utm_epsg_from_latlon` (derives the UTM EPSG code from the GPS centroid). The function is robust: if no GPS EXIF is found in any image, registration is skipped with a warning rather than failing the job.
- `feat(sfm)`: Add `geo_registration_max_error: float = 3.0` to `ColmapSettings` (env var `COLMAP_GEO_REGISTRATION_MAX_ERROR`). Controls `--robust_alignment_max_error` passed to `colmap model_aligner`.
- `feat(orthomosaic)`: Add module-level `_load_geo_reference(workspace)` helper to `orthomosaic_service.py`. Recursively searches the workspace for `geo_reference.json` so it works regardless of the SFM run directory name.
- `feat(sfm)`: Add no-op `geo_register()` to `OpenSFMService` for interface compatibility. OpenSfM handles geo-registration internally via GPS priors, so no external alignment step is required.

### Infrastructure

- `refactor(sfm)`: Add `math` and `PIL` / `PIL.ExifTags` imports to `colmap_service.py` to support EXIF GPS extraction without introducing new dependencies (Pillow is already a transitive dependency).
