# v0.9.2 — Upload Status Callback, Product Metadata

## Summary

AI Gateway now sends upload status callbacks to backend after product uploads complete, enabling proper failure handling. Product metadata (resolution, bands, statistics) is extracted from orthomosaic service output and passed through during uploads.

## All Changes

### Bug Fixes

- `fix(uploads)`: Product uploads were fire-and-forget with no failure reporting. Jobs showed "completed" even when uploads failed. Now sends `upload_status` callback after uploads complete.
- `fix(uploads)`: Product metadata (`resolution_cm`, `bands`, `stats`) was never passed to backend during uploads, leaving product table columns empty.

### Features

- `feat(backend-client)`: New `send_upload_status()` method sends upload results (uploaded/failed product lists) to backend callback endpoint.
- `feat(uploads)`: `_upload_stage_products_background` now sends upload status callback to backend after all uploads complete or fail.
- `feat(uploads)`: `_extract_orthomosaic_metadata()` helper reads statistics JSON from orthomosaic service output to extract resolution (from geotransform), band count, and raster dimensions.
- `feat(uploads)`: Orthomosaic product uploads now pass `resolution_cm`, `bands`, and `stats` metadata. Vegetation index uploads include band type info.
- `feat(uploads)`: `_upload_product()` inner function now accepts optional `resolution_cm`, `bands`, `stats` parameters.

### Infrastructure

- `test(uploads)`: Updated `TestUploadStageProductsBackground` tests to verify `backend_client.send_upload_status` is called with correct upload/failure data.
- `test(uploads)`: Added `TestExtractOrthomosaicMetadata` test class with 4 tests (empty outputs, missing file, valid statistics, malformed JSON).

## 🔌 Backend Contract Changelog

| Change | Impact | Action Required |
|--------|--------|-----------------|
| AI sends `type: "upload_status"` callback after product uploads | Backend can detect and handle upload failures | Backend must handle `upload_status` callback type (done in backend v0.5.0) |
| Product uploads now include `resolution_cm`, `bands`, `stats` in init payload | Product table rows will have populated metadata columns | No action — backend already accepts these fields |

## 📡 Inter-Service Changelog

| Change | Impact | Action Required |
|--------|--------|-----------------|
| `_upload_stage_products_background` now requires `backend_client` parameter | Upload background task sends status callback after completion | All callers must pass `backend_client` (already updated) |
| `_upload_product` accepts optional metadata parameters | Product metadata flows from service output to backend | No action — metadata is automatically extracted when available |
