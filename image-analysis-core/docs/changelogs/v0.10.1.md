# v0.10.1 — Upload Retry, Non-Blocking Uploads, S3 Healthcheck Diagnostics

## Summary

Fixes critical issues: (1) upload failures no longer block or break the processing pipeline — uploads are fully non-blocking and the pipeline completes even if uploads fail, (2) retrying a job from the UPLOADING stage now actually re-uploads all products instead of silently doing nothing, (3) the S3 healthcheck now provides detailed credential diagnostics with fallback to standard AWS env vars, and (4) upload results are persisted properly via `JobStateManager` in Redis.

## All Changes

### Bug Fixes

- `fix(pipeline)`: Upload failures no longer block or break the processing pipeline. The `_upload_stage_products_background` fire-and-forget wrapper now logs clearly that the pipeline continues when uploads fail, and stores upload results (success/failure per product) in Redis job state for retry capability.
- `fix(retry)`: `run_pipeline_task` now handles `UPLOADING` and `PUBLISHING` as starting stages. Previously, retrying from the uploading stage fell through to `else: logger.warning("Unexpected initial stage")` and did nothing — the retry was silently ignored.
- `fix(pipeline)`: `trigger_next_stage` UPLOADING handler now also completes the PUBLISHING stage before sending the completion callback, preventing the pipeline from getting stuck between UPLOADING and COMPLETED.
- `fix(retry)`: `run_pipeline_task` now accepts `product_upload_client` parameter so upload retry can actually call the upload API. The `run_job` endpoint passes it through.

### Features

- `feat(uploads)`: New `_store_upload_results_in_state()` helper persists upload outcomes (uploaded/failed product lists per stage) into `job.stage_results["upload_results"]` in Redis, enabling retry to know what previously failed.
- `feat(retry)`: Upload retry (`starting_stage=uploading`) iterates over all completed processing stages (calibration, sfm, orthomosaic), re-uploads their products, and reports combined upload status to backend before completing the job.
- `feat(health)`: S3 healthcheck now detects and reports the credential source (explicit env vars, ECS task role, web identity token, shared credentials file, or none) and provides actionable hints when credentials are missing.
- `feat(health)`: S3 healthcheck validates boto3 credential resolution before making bucket calls — logs resolved credential method and access key prefix for debugging. Logs masked settings values (`access_key_id`, `secret_access_key` length) for diagnostics.
- `feat(health)`: S3 healthcheck falls back to standard `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` env vars when `AWS_S3_`-prefixed credentials are not set.
- `feat(uploads)`: band_manifest upload now logs success/failure status and includes `bands_count` in diagnostics. Failure logs include connectivity hints.

### Infrastructure

- `refactor(state)`: New `JobStateManager.update_stage_result()` method for updating stage results in Redis. Upload result persistence now uses this proper API instead of directly accessing internal Redis methods.
- `refactor(jobs)`: `_store_upload_results_in_state()` refactored to use `job_state_manager.update_stage_result()` — clean separation of concerns, no more direct access to `_get_key()` or `redis.set()`.
- `refactor(jobs)`: `run_pipeline_task` signature changed — `product_upload_client: ProductUploadClient | None = None` inserted after `backend_client`. Existing callers passing positional `temp_manager` must update.
- `test(jobs)`: Updated `TestRunPipelineTask` tests to pass `temp_manager` as keyword argument for compatibility with new signature.
