# v0.10.24 — Fix SFM/DSM doming via DJI factory-intrinsic seeding (FULL_OPENCV + k3)

## Summary

The DSM produced over flat terrain showed a pronounced "doming"/bowl artifact —
approximately 4.5 m of false radial curvature, with 89.9 % of the total elevation
variance attributable to a smooth quadratic shape. Root cause: under a single-altitude
nadir-only flight geometry, focal length is weakly constrained by the scene, so
COLMAP/GLOMAP self-calibration allowed the focal estimate to drift (~5 146 px measured
vs the DJI factory value of ~3 713 px), trading focal length against flying height and
bending the reconstructed surface — the classic interior/exterior-orientation coupling
that produces photogrammetric doming. The fix parses the DJI factory calibration
directly from each image's `drone-dji:DewarpData` XMP, seeds it into the COLMAP
database as a FULL_OPENCV camera (retaining the k3 radial-distortion term absent from
plain OPENCV), and then locks the intrinsics so neither the GLOMAP global mapper nor the
COLMAP bundle adjuster can drift them. On a full-pipeline validation run (119 M3M images)
sparse tracks rose from 93 k to 187 k, and DSM dome curvature collapsed from ~4.5 m to
0.21 m peak-to-trough (~95 % reduction); the remaining ~3 m relief is real planar ground
tilt (82.2 % of variance), not an artifact. The feature is opt-in via
`COLMAP_SEED_FACTORY_INTRINSICS=true` in `.env` and gracefully falls back to
self-calibration when no DewarpData is present (non-DJI drones).

## Bug Fixes

### fix(sfm): seed DJI factory intrinsics into COLMAP to prevent focal-length drift and DSM doming

**File:** `services/sfm/app/core/services/colmap_service.py`

**Root cause**

Under nadir-only single-altitude flight geometry, the focal length is almost collinear
with flying height in the bundle-adjustment Jacobian, making it weakly constrained.
COLMAP/GLOMAP self-calibration drifted the focal from the DJI factory value of ~3 713 px
to ~5 146 px. To satisfy the bundle, the reconstructed point cloud compressed in Z,
introducing a smooth radial bowl into the DSM (~4.5 m peak-to-trough curvature; 89.9 %
of elevation variance was quadratic). A secondary issue: the OPENCV camera model in use
has no k3 slot; dropping k3 (~20 % of edge radial distortion) itself contributed to the
doming and was not correctable by switching to SIMPLE_RADIAL.

**Fix**

- Added `_parse_dji_dewarp_intrinsics` — reads `drone-dji:DewarpData` from the first
  image's XMP sidecar/embedded metadata and extracts `fx, fy, cx, cy, k1, k2, p1, p2,
  k3`. Returns `None` and logs a warning when the tag is absent.
- Added `_seed_camera_intrinsics` — writes the parsed parameters into the COLMAP
  database as a FULL_OPENCV camera (model ID 6; parameter order `fx, fy, cx, cy, k1, k2,
  p1, p2, k3, k4`) and sets `prior_focal_length = 1` to signal to COLMAP that the value
  is trustworthy.
- Added `_intrinsics_are_seeded` — reads the `prior_focal_length` flag back from the
  database; used as a resume-safe guard so a restarted job does not re-seed an already
  patched camera.
- Bundle-adjuster flags appended when seeding is active:
  - GLOMAP global mapper: `--BundleAdjustment.optimize_intrinsics 0`
    `--BundleAdjustment.optimize_principal_point 0`
  - COLMAP `bundle_adjuster`: `--BundleAdjustment.refine_focal_length 0`
    `--BundleAdjustment.refine_extra_params 0`
    `--BundleAdjustment.refine_principal_point 0`
- All seeding code is gated on `ColmapSettings.seed_factory_intrinsics` (default
  `False`); the code path is entirely skipped when the flag is off, preserving the
  prior behaviour.

**Validated result (119-image M3M dataset)**

| Metric | Before | After |
|---|---|---|
| COLMAP focal estimate | ~5 146 px | 3 713.29 px (factory) |
| Camera model | OPENCV | FULL_OPENCV |
| k3 term | dropped | −0.027 (factory) |
| Sparse track count | ~93 k | ~187 k |
| DSM dome curvature (peak-to-trough) | ~4.5 m | 0.21 m (~95 % reduction) |
| Elevation std | 1.02 m | 0.535 m |
| Residual variance (planar tilt, real) | — | 82.2 % |

## Features

### feat(sfm): add `COLMAP_SEED_FACTORY_INTRINSICS` env-var opt-in flag

**File:** `.env.example`

Added `COLMAP_SEED_FACTORY_INTRINSICS=false` to `.env.example` with a comment
explaining the doming-fix opt-in. Backed by `ColmapSettings.seed_factory_intrinsics`
(Pydantic `bool`, default `False`) in the SFM settings model. When set to `true` the
three new functions in `colmap_service.py` activate; when false or absent the service
behaves identically to v0.10.23.

## Breaking Changes

No changes. The new seeding path is entirely opt-in (default `False`). Existing
deployments that do not set `COLMAP_SEED_FACTORY_INTRINSICS=true` will see no
behavioural difference.
