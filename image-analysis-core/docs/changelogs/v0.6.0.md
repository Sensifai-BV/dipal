# v0.6.0 — Multispectral Analysis Pipeline

## Summary

Major feature release adding end-to-end multispectral analysis capabilities.
Calibration now performs DN-to-reflectance conversion, orthorectified spectral
bands are produced alongside the RGB orthomosaic, and vegetation indices
(NDVI, NDRE, GNDVI) are computed and uploaded as Cloud Optimized GeoTIFFs.
A new `analysis_mode` parameter (`fast` / `full`) controls whether the
multispectral pipeline runs.

---

## All Changes

### Features

- **feat(backend):** Add `analysis_mode` field (`fast`/`full`) to
  `ProcessingJob` model, serializer, entity, use case, and Celery task.
  Default: `fast`. Migration `0005_add_analysis_mode`.
- **feat(calibration):** DN-to-reflectance conversion now runs in the
  calibration pipeline. Spectral images are saved as float32 reflectance
  TIFs (0–1 range) instead of scaled uint16.
- **feat(sfm):** Fast mode doubles the effective GSD before converting to
  COLMAP `max_image_size`, reducing reconstruction time.
- **feat(orthomosaic):** New `ms_orthorectification` module orthorectifies
  calibrated reflectance bands onto the DSM grid (median composite).
- **feat(orthomosaic):** New `vegetation_indices` module computes NDVI, NDRE,
  and GNDVI from orthorectified bands, output as COGs.
- **feat(orthomosaic):** `OrthomosaicService.add_overviews()` method adds
  gdaladdo overview pyramids.
- **feat(gateway):** API Gateway enriches orthomosaic parameters with
  calibration results (`calibration_path`, `is_multispectral`,
  `band_manifest`, `has_reflectance`, `sfm_run_path`).
- **feat(gateway):** Uploads NDVI, NDRE, GNDVI, and multiband reflectance
  products from orthomosaic stage.
- **feat(orthomosaic):** Multi-resolution output generates downsampled
  orthomosaics at 2×, 4×, and 8× the native GSD as separate COG files.
  Uses `gdal_translate -outsize` with cubic interpolation.
- **feat(gateway):** Uploads `orthomosaic_2x`, `orthomosaic_4x`,
  `orthomosaic_8x` product types from multi-resolution outputs.
- **feat(shared):** New `shared/colmap/` package with binary model reader
  for cameras.bin and images.bin.

### Infrastructure

- **ci(backend):** Django migration `0005_add_analysis_mode.py`.

## 🔌 Backend Contract Changelog

| Change | Impact | Action Required |
|--------|--------|-----------------|
| New optional field `analysis_mode` on `POST /v1/api/jobs/start-job/` | Accepts `"fast"` (default) or `"full"`. Existing requests without this field default to `fast`. | No action for current behaviour; pass `"full"` to enable multispectral products. |
| New column `analysis_mode` on `ProcessingJob` model | Shown in job list endpoint | Run migration `0005_add_analysis_mode`. |
| New product types uploaded: `ndvi`, `ndre`, `gndvi`, `calibrated_reflectance` | These are only produced when `analysis_mode=full` and dataset is multispectral | Backend already has these product types in `Product.ProductType`. No schema change needed. |
| New product types uploaded: `orthomosaic_2x`, `orthomosaic_4x`, `orthomosaic_8x` | Downsampled orthomosaics at 2×, 4×, 8× native GSD. Produced for all jobs (fast and full mode). | Backend needs these 3 new product type choices in `Product.ProductType`. |
| `analysis_mode` included in `ProcessingJobListSerializer` response | Additional field in job list JSON | Frontend may display if desired; backward-compatible. |
