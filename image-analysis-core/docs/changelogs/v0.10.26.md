# v0.10.26 — Upload the UTM dense point cloud as a downloadable product

## Summary

The SFM stage produces `fused_utm.ply` (the dense cloud reprojected to UTM, with
human-readable easting/northing/elevation), but the gateway only uploaded `fused.ply`
(the local SFM frame, with meaningless coordinates) as the "pointcloud" product. A
tester who downloaded the point-cloud product therefore could not read real-world
coordinates. This release uploads `fused_utm.ply` as a new `pointcloud_utm` product
alongside the existing ones, so the downloadable cloud carries usable UTM coordinates.
Also adds [ADR 0004](../architecture/adr/0004-multispectral-single-band-speckle.md)
documenting the multispectral single-band speckle (DSM-jitter / sensor-noise /
super-native sampling) and its remedies — analysis-only, no code change.

## Features

### feat(orthomosaic): upload `fused_utm.ply` as the `pointcloud_utm` product

**File:** `api_gateway/app/api/v1/endpoints/jobs.py`

The SFM product-upload set now includes `fused_utm.ply` as product type
`pointcloud_utm`, alongside the existing `pointcloud` (`fused.ply`) and `mesh`
(`meshed-poisson.ply`). `_upload_product` already skips a missing file gracefully, so a
build without PDAL (no `fused_utm.ply`) simply logs and continues. The UTM cloud is the
one consumers should open to extract coordinates; `fused.ply` (local frame) and
`fused_georef.ply` (ECEF) are not human-friendly.

> Requires the SFM image built with PDAL (v0.10.25) so `fused_utm.ply` is produced, and
> the backend/frontend `pointcloud_utm` product type (committed in their repos).
