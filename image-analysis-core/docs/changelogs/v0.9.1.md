# v0.9.1 — Non-blocking Pipeline Uploads, Band Organizer Fix, Calibration Re-run Fix

## Summary

Bug-fix release that eliminates blocking uploads from the processing pipeline,
fixes a manifest path-update bug in the band organizer, and fixes calibration
re-runs scanning an incomplete `images/` directory instead of using already-
organized band folders. Together these fixes ensure the pipeline never stalls
between stages waiting for large product uploads (e.g. 300 MB mesh), and that
re-triggered calibration jobs process the full dataset.

---

## All Changes

### Bug Fixes

- `fix(jobs)`: Make product uploads non-blocking across all pipeline stages.
  `process_callback_async` now triggers the next stage **before** firing off
  uploads via `asyncio.create_task(_upload_stage_products_background(...))`.
  Previously, `await upload_stage_products(...)` blocked the pipeline between
  stages — SFM product upload (119 MB pointcloud + 314 MB mesh) could delay
  orthomosaic triggering by several minutes.
- `fix(orthomosaic)`: Fix PDAL `--threads 0` crash. Default `pdal_threads = 0`
  with condition `!= 1` caused `--threads 0` to be passed to PDAL, which
  rejects 0 as invalid. Changed condition to `> 0` so 0 means "omit the flag
  entirely" (PDAL defaults to all cores).
- `fix(band-organizer)`: Update `info.file_path` when destination file already
  exists in `organize_by_band()`. Previously, when `dst.exists()` the organizer
  skipped the move but left `file_path` pointing at the stale `images/` source.
  This caused the manifest saved to disk to contain incorrect paths.
- `fix(calibration)`: On re-runs, detect existing band folders and rebuild the
  manifest from them instead of re-scanning the (potentially incomplete)
  `images/` directory. Adds `_has_organized_bands()` check and
  `_rebuild_manifest_from_bands()` to scan the authoritative band folders
  (green/, rgb/, nir/, etc.) and produce a correct manifest with full image
  counts.

### Tests

- `test(jobs)`: Add `TestUploadStageProductsBackground` — 3 tests covering the
  fire-and-forget wrapper: success, partial failure, and exception handling.
- `test(jobs)`: Add `TestNonBlockingUploadPattern` — 4 tests verifying
  `asyncio.create_task` is used for uploads after `trigger_next_stage` across
  calibration, SFM, orthomosaic final-stage callbacks.
- `test(jobs-ext)`: Add `test_orthomosaic_multi_resolution_all_scales` — verifies
  upload of 2x, 4x, 8x multi-resolution outputs.
- `test(jobs-ext)`: Add `test_orthomosaic_all_vegetation_indices` — verifies
  NDVI, NDRE, and GNDVI vegetation index uploads.
- `test(jobs-ext)`: Add `test_orthomosaic_full_multispectral_pipeline` — verifies
  all 10 product types in a complete multispectral pipeline output.
- `test(band-detection)`: Add `test_organize_updates_path_when_destination_exists`
  — verifies `file_path` is updated even when `dst.exists()`.
