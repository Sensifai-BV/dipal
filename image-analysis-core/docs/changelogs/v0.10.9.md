# v0.10.9 — Geo-Registration Fix: TIFF GPS EXIF + model_aligner Corrections

**Date:** 2026-05-04

Three bugs that together prevented `geo_reference.json` from ever being written
for Micasense datasets, causing all SFM outputs to be generated without a CRS.

---

## Bug Fixes

### 1. `_extract_gps_from_images`: JPEG-only `_getexif()` replaced with TIFF-compatible `getexif()`

**File:** `services/sfm/app/core/services/colmap_service.py`

`_extract_gps_from_images` was using PIL's private `img._getexif()` method, which is
implemented only on `JpegImagePlugin` and returns `None` for all other formats.  The
RGB images produced by the Micasense calibration pipeline are TIFF files, so this
method always returned `None`, the GPS list was always empty, and `geo_register` exited
early without writing `geo_reference.json`.

**Fix:** switched to Pillow's public `img.getexif()` API (available since Pillow 6.0,
works for both JPEG and TIFF) followed by `exif.get_ifd(0x8825)` to read the GPS
sub-IFD directly.  Added a guard that skips any image whose GPS IFD is missing the
mandatory `GPSLatitude` / `GPSLongitude` keys.  Removed the now-unused `TAGS` import.

### 2. `geo_register`: removed unsupported `--robust_alignment` flags

**File:** `services/sfm/app/core/services/colmap_service.py`

The `colmap model_aligner` invocation included `--robust_alignment 1` and
`--robust_alignment_max_error <value>`, which are not recognised by the COLMAP build
deployed in the container.  COLMAP printed:

```
Failed to parse options - unrecognised option '--robust_alignment'.
```

and exited with return code 1, so `geo_reference.json` was never written even when GPS
extraction succeeded.

**Fix:** removed both flags from the command list.  The correct error-threshold flag
(`--alignment_max_error`) was identified after this release and applied in v0.10.10.

### 3. `orthomosaic_endpoint`: symlink `geo_reference.json` into orthomosaic workspace

**File:** `services/orthomosaic_generation/app/api/v1/endpoints/orthomosaic_endpoint.py`

The orthomosaic service searches for `geo_reference.json` via `rglob` within its own
job workspace.  Previously only the `dense/` directory was symlinked from the SFM run
path; `geo_reference.json` (written alongside `dense/` in the SFM run directory) was
never visible to the orthomosaic service.

**Fix:** after creating the `dense/` symlink, also create a symlink for
`geo_reference.json`.  A warning is logged when the source file is absent so that
missing geo-registration is visible in logs without failing the job.

## Tests

**`tests/unit/test_colmap_service.py`** — `TestExtractGpsFromImages`

Updated all existing mocks from `mock_img._getexif.return_value = exif_dict` to the
new pattern:

```python
mock_exif = MagicMock()
mock_exif.get_ifd.return_value = {<integer GPS tag IDs>: value, ...}
mock_img.getexif.return_value = mock_exif
```

Added one new test case:

| Test | Description |
|------|-------------|
| `test_skips_tiff_without_gps_ifd` | Verifies `.tif` images with an empty GPS IFD are skipped (mirrors the real Micasense failure mode) |

All 34 tests in `test_colmap_service.py` pass (1 pre-existing unrelated failure in
`test_get_image_path_prefer_rgb` excluded from count — that function was never
implemented to prefer `rgb/`).
