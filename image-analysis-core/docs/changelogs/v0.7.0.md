# v0.7.0 — SQS-Based Job Dispatch for Autoscaling

## Summary

Introduces dual-mode job dispatch (`http` / `sqs`) so that the API gateway can
publish processing jobs to AWS SQS queues instead of calling services via HTTP.
Each processing service (calibration, SFM, orthomosaic) now includes an optional
SQS consumer that polls its queue on startup.  The existing HTTP dispatch path
remains the **default** (`DISPATCH_MODE=http`), preserving full local
development and testing compatibility.

---

## All Changes

### Features

- `feat(infra)`: Add `SQSSettings` pydantic model for SQS configuration
  (`SQS_` env prefix, queue URLs, DLQ URLs, polling settings).
- `feat(infra)`: Add `SQSClient` — thin boto3 wrapper with
  `send_message`, `receive_messages`, `delete_message`, `change_visibility`,
  and `get_queue_url` helpers. Supports both IAM role and explicit credentials.
- `feat(infra)`: Add `SQSConsumer` — async polling consumer that runs alongside
  the FastAPI HTTP server. Long-polls the queue, deserializes JSON, invokes the
  handler coroutine, and deletes messages on success (leaves for DLQ on failure).
- `feat(gateway)`: Add `SQSDispatcher` client with `dispatch_calibration`,
  `dispatch_sfm`, and `dispatch_orthomosaic` methods. Uses the same message
  format as the HTTP client payloads.
- `feat(gateway)`: Add `DispatchSettings` (`DISPATCH_MODE` env var) to switch
  between HTTP and SQS dispatch at runtime.
- `feat(gateway)`: Update `run_pipeline_task`, `trigger_next_stage`,
  `process_callback_async`, `resume_job`, and `simulate_callback` in jobs
  endpoint to route through SQS dispatcher when `DISPATCH_MODE=sqs`.
- `feat(sfm)`: Add SQS consumer integration via FastAPI lifespan — polls
  `SQS_SFM_QUEUE_URL` and invokes `run_sfm_task` directly.
- `feat(calibration)`: Add SQS consumer integration via FastAPI lifespan —
  polls `SQS_CALIBRATION_QUEUE_URL` and invokes `run_calibration_task` directly.
- `feat(orthomosaic)`: Add SQS consumer integration via FastAPI lifespan —
  polls `SQS_ORTHOMOSAIC_QUEUE_URL` and invokes `run_orthomosaic_task` directly.

### Infrastructure

- `infra(message_queue)`: Export `SQSSettings`, `SQSClient`, `SQSConsumer` from
  `infrastructure.message_queue.__init__`.
- `infra(gateway)`: Register `DispatchSettings`, `SQSSettings`, `SQSClient`,
  `SQSDispatcher` in API gateway DI container.
- `infra(config)`: Add SQS and dispatch configuration section to `.env.example`.

### Tests

- `test(sqs)`: Add 17 unit tests for `SQSSettings`, `SQSClient`, and
  `SQSConsumer` (settings defaults, env overrides, send/receive/delete, queue
  URL resolution, consumer start/stop, message processing, invalid JSON handling,
  handler failure semantics).
- `test(dispatcher)`: Add 6 unit tests for `DispatchSettings` and  `SQSDispatcher`
  (default HTTP mode, SQS mode from env, dispatch to each service queue,
  default empty parameters).

### Bug Fixes

No changes.

### Breaking Changes

No changes.

## 📡 Inter-Service Changelog

| Change | Impact | Action Required |
|--------|--------|-----------------|
| New dispatch mode `DISPATCH_MODE=sqs` | When set, API gateway publishes jobs to SQS instead of HTTP | Set `DISPATCH_MODE=sqs`, `SQS_ENABLED=true`, and queue URLs in production `.env` |
| New env vars: `SQS_*` family | Configures SQS queues, credentials, and polling | Populate queue URLs from AWS SQS console; set `SQS_USE_AWS_ROLE=true` on ECS |
| Service lifespan consumer | Each service starts an SQS consumer on startup when `SQS_ENABLED=true` | Deploy updated service images with SQS env vars |
| Callback path unchanged | Services still HTTP-callback to API gateway on completion | No action required |
