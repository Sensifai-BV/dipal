# v0.10.14 — Dense Fusion Fix: Pipeline Reorder + Correct fusion_input_type

**Date:** 2026-05-11

Two root causes for `stereo_fusion produced 0 fused points`, both independently
sufficient to cause the failure.

---

## Bug Fixes

### 1. `geo_register` ran before dense reconstruction, corrupting depth maps

**Files:** `services/sfm/app/core/algorithms/sfm_pipeline.py`,
`services/sfm/app/core/services/colmap_service.py`

`geo_register` replaced `sparse/0` with a COLMAP model whose camera positions are in
ECEF coordinates (~6,370,000 m from Earth's centre).  `undistort` and
`patch_match_stereo` then ran using those ECEF-scale camera positions.

`stereo_fusion` consistency checks compare depth values across overlapping views.  In
ECEF space the "depth" of a drone photo is on the order of millions of metres, so any
two estimates that agree within 5 % still differ by tens of thousands of metres —
every pixel fails consistency and is rejected.  The result is a `fused.ply` with 0
points.

**Fix (two-part):**

1. **Pipeline reorder** (`sfm_pipeline.py`): `geo_register` moved to run **after**
   `compute_depthmaps`, so the entire dense pipeline operates in local SFM space.

   Before:
   ```
   bundle_reconstruction → geo_register → undistort → compute_depthmaps → mesh
   ```
   After:
   ```
   bundle_reconstruction → undistort → compute_depthmaps → geo_register → mesh
   ```

2. **`geo_register` no longer replaces `sparse/0`** (`colmap_service.py`): the
   function now runs `model_aligner` into a temporary directory, extracts only
   `geo_transform.txt`, then discards the aligned model.  `sparse/0` is never
   modified.  `mesh()` remains responsible for applying `geo_transform.txt` to
   `fused.ply` → `fused_georef.ply` (ECEF), which PDAL then reprojects to UTM.

---

### 2. `fusion_input_type=geometric` reads unfiltered depth maps

**File:** `services/sfm/app/core/services/colmap_service.py`

When `PatchMatchStereo.geom_consistency=1`, `patch_match_stereo` runs two passes:

1. **Photometric pass** — writes `photometric.bin` with `filter=1` applied.
2. **Geometric consistency pass** — writes `geometric.bin` **without** filtering
   (COLMAP does not re-apply the filter on the geometric pass; the filtered
   photometric maps are its input).

`fusion_input_type=geometric` told `stereo_fusion` to read the unfiltered
`geometric.bin` maps.  With no depth filtering, virtually every pixel has
inconsistent depth estimates across views, so stereo_fusion fuses 0 points.
COLMAP itself emits: *"filtering must be enabled for the last call to patch match
stereo"* — i.e. the geometric pass is the "last call" and it has no filter.

**Fix:** `fusion_input_type` default changed from `geometric` → `photometric`.
`stereo_fusion` now reads the filtered `photometric.bin` maps.  The geometric pass
still runs and its output is used internally by patch_match_stereo to refine depth
estimates; only the fusion input changes.

## Pipeline After This Release

```
extract_metadata
extract_features
match_features
create_tracks
compute_reconstruct       (glomap — local SFM space)
bundle_reconstruction     (local SFM space)
undistort                 (reads sparse/0 — local SFM space)  ✓
compute_depthmaps         (patch_match_stereo + stereo_fusion — local SFM space)  ✓
geo_register              (model_aligner → geo_transform.txt only; sparse/0 untouched)
mesh                      (fused.ply → fused_georef.ply via geo_transform.txt)
compute_statistics
export_report
```
