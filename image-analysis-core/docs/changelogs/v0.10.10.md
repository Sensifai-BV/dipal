# v0.10.10 — PDAL OOM Fix + User-Selected GSD Wiring + `--alignment_max_error` Correction

**Date:** 2026-05-04

Three fixes in the orthomosaic and geo-registration pipeline.

---

## Bug Fixes

### 1. `geo_register`: replace unknown `--max_error` with correct `--alignment_max_error`

**File:** `services/sfm/app/core/services/colmap_service.py`

After removing `--robust_alignment` in v0.10.9, the `colmap model_aligner` invocation
had no error-threshold flag.  COLMAP exited with:

```
You must provide a maximum alignment error > 0.
```

An intermediate attempt used `--max_error`, which is also not a valid flag for this
command.  The correct flag (verified against `colmap model_aligner --help` inside the
running container) is `--alignment_max_error`.

**Fix:** replaced `--max_error` with `--alignment_max_error` bound to
`ColmapSettings.geo_registration_max_error` (default `3.0` m — appropriate for
consumer-grade non-RTK GPS).

### 2. PDAL DSM generation: OOM kill caused by 1 cm default resolution

**Files:** `services/orthomosaic_generation/app/core/services/orthomosaic_service.py`,
`.env`, `.env.example`

`writers.gdal` allocates a raster covering the full UTM bounding box of the point
cloud at the requested resolution.  With the default `dsm_resolution = 0.01` m (1 cm)
and a typical survey area of 500 m × 500 m, the in-memory raster is:

```
50 000 × 50 000 × float32 ≈ 10 GB
```

Docker SIGKILL (rc = -9) terminated the PDAL process before it could write any output.

**Fix:** changed the default resolution from `0.01` m (1 cm) to `0.05` m (5 cm) in:
- `OrthomosaicSettings.dsm_resolution`
- `OrthomosaicSettings.ortho_resolution`
- `ORTHOMOSAIC_DSM_RESOLUTION` in `.env` and `.env.example`
- `ORTHOMOSAIC_ORTHO_RESOLUTION` in `.env` and `.env.example`

5 cm is the fallback only — the user-selected GSD (see fix 3 below) takes precedence
at runtime.  Memory for the same 500 m × 500 m area at 5 cm:

```
10 000 × 10 000 × float32 ≈ 400 MB ✓
```

### 3. `orthomosaic_endpoint`: user-selected GSD was silently ignored

**Files:** `services/orthomosaic_generation/app/api/v1/endpoints/orthomosaic_endpoint.py`,
`services/orthomosaic_generation/app/core/services/orthomosaic_service.py`

The frontend panel lets the user choose a GSD (e.g. 5 cm/px).  This value is sent by
the Django backend as `parameters["resolution_gsd"]` (in cm) and forwarded unchanged
through the API gateway to the orthomosaic service.  However, `run_orthomosaic_task`
never read that key, and `OrthomosaicService()` was always instantiated without any
overrides, so it always used the `.env` default regardless of the user's choice.

**Fix:**
- `OrthomosaicService.__init__` now accepts an `additional_settings: dict | None`
  argument that is forwarded to `OrthomosaicSettings(...)`.
- `run_orthomosaic_task` reads `parameters["resolution_gsd"]` (cm), converts it to
  metres (`/ 100`), and passes `dsm_resolution` and `ortho_resolution` overrides to
  `OrthomosaicService`.
- Falls back to the `.env` value when `resolution_gsd` is absent (backward-compatible
  with old jobs and resume calls).

## Configuration Changes

| Variable | Old default | New default |
|---|---|---|
| `ORTHOMOSAIC_DSM_RESOLUTION` | `0.01` | `0.05` |
| `ORTHOMOSAIC_ORTHO_RESOLUTION` | `0.01` | `0.05` |

> **Action required:** restart the `orthomosaic_generation` container after updating
> `.env` so the new defaults take effect.
