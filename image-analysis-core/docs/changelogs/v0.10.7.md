# v0.10.7 — Docker Infrastructure Hardening & COLMAP Vocab Tree Fix

**Date:** 2026-05-03

Three Docker infrastructure improvements: volume names are now pinned so they
survive project-directory renames, all services have explicit container names
for predictable `docker exec` / log access, and COLMAP's sequential matcher
no longer downloads a ~200 MB vocabulary tree from GitHub on every job run.

Previously, Docker volume names were derived from the parent directory name
(`image-analysis-core_shared_processing_data`), so renaming the project folder
silently created orphaned volumes and new empty ones — losing cached COLMAP
databases and shared processing data between runs.

The vocabulary tree download happened because `COLMAP_SEQUENTIAL_LOOP_DETECTION=1`
was enabled but no local tree path was configured, causing COLMAP to
auto-fetch `vocab_tree_faiss_flickr100K_words256K.bin` (~200 MB) from GitHub
releases at the start of every SFM job.

---

## All Changes

### Bug Fixes

- `fix(docker)`: Pin all named volume names with explicit `name:` directives in
  `docker-compose.yml` so volumes are always named `photogear_shared_processing_data`,
  `photogear_sfm_database`, and `photogear_redis_data` regardless of the host
  directory name. Eliminates silent data loss on project-folder renames.

### Features

- `feat(docker)`: Add `container_name:` to all four services (`photogear-api_gateway`,
  `photogear-calibration`, `photogear-sfm`, `photogear-orthomosaic_generation`) for
  stable, predictable container addressing across restarts.
- `feat(sfm)`: Bake COLMAP vocabulary tree into the SFM Docker image at build time.
  The `services/sfm/Dockerfile` now downloads
  `vocab_tree_faiss_flickr100K_words256K.bin` from the COLMAP 3.11.1 GitHub release
  during the image build and stores it at
  `/usr/local/share/colmap/vocab_tree_flickr100K_words256K.bin`.  COLMAP never
  downloads the file at runtime again.
- `feat(sfm)`: Add vocab tree bind mount to `docker-compose.yml` for local
  development without a full image rebuild.  If `data/vocab_tree_faiss_flickr100K_words256K.bin`
  exists on the host (controlled by `COLMAP_VOCAB_TREE_HOST_PATH`), it is mounted
  read-only to the same container path, overriding the baked-in copy when present.

### Configuration

- `config(.env)`: Add `COLMAP_SEQUENTIAL_VOCAB_TREE_PATH` pointing to the
  in-container path `/usr/local/share/colmap/vocab_tree_flickr100K_words256K.bin`.
  Consumed by `ColmapSettings.sequential_vocab_tree_path`; pydantic-settings maps
  it via the `COLMAP_` prefix automatically.
- `config(.env)`: Add `COLMAP_VOCAB_TREE_HOST_PATH=./data/vocab_tree_faiss_flickr100K_words256K.bin`
  to control which host file the docker-compose bind mount uses.

## Deployment Notes

**Existing deployments (volume migration):**

If you have data in old volumes (`image-analysis-core_shared_processing_data`,
`image-analysis-core_sfm_database`, `image-analysis-core_redis_data`), migrate
them before restarting:

```sh
# Example for shared_processing_data
docker volume create photogear_shared_processing_data
docker run --rm \
  -v image-analysis-core_shared_processing_data:/from \
  -v photogear_shared_processing_data:/to \
  alpine sh -c "cp -a /from/. /to/"
```

**Vocab tree for local dev (no rebuild):**

Place the pre-downloaded file in `image-analysis-core/data/` and it will be
mounted automatically:

```sh
wget -O image-analysis-core/data/vocab_tree_faiss_flickr100K_words256K.bin \
  https://github.com/colmap/colmap/releases/download/3.11.1/vocab_tree_faiss_flickr100K_words256K.bin
```

**Vocab tree baked into image (production):**

```sh
docker compose build sfm
```
