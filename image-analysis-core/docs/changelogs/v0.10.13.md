# v0.10.13 — Geo-Registration: Wire Camera Outlier Filter + Alignment Diagnostics

**Date:** 2026-05-11

Two fixes to `geo_register` in `ColmapService`.  Both symbols (`_filter_misaligned_cameras`,
Scale/RMSE regex scanning) were implemented in the codebase since v0.10.11 but were never
wired into the function that calls `model_aligner`, so they had no effect at runtime.

---

## Bug Fixes

### 1. `geo_register`: `_filter_misaligned_cameras()` implemented but never called

**File:** `services/sfm/app/core/services/colmap_service.py`

`_filter_misaligned_cameras()` was written (complete with pycolmap API usage and ECEF
distance calculation) but the call site was missing entirely from `geo_register`.
After `model_aligner` writes `sparse/0_aligned`, a tail of GLOMAP cameras can deviate
tens of metres from their true GPS position.  Those cameras produce incoherent depth
maps that cause `stereo_fusion` to discard nearly every pixel even with
`fusion_max_depth_error = 0.05`.

**Fix:** added the call to `_filter_misaligned_cameras(sparse_aligned, ref_images_txt,
geo_registration_outlier_filter_m)` immediately after `_run_command` returns and before
the atomic `0_aligned → sparse/0` swap.  Removed cameras are re-saved into
`sparse_aligned` so the swap installs the cleaned model.  A warning log shows the
count of cameras removed and kept.

Set `COLMAP_GEO_REGISTRATION_OUTLIER_FILTER_M=0` to disable filtering entirely.

---

### 2. `geo_register`: alignment quality diagnostics never executed

**File:** `services/sfm/app/core/services/colmap_service.py`

The Scale and RMSE diagnostic described in v0.10.11 changelog (fix #4) was never
implemented in code.  `_run_command` output was not captured and no regex was applied
to it, so bad alignment transforms (scale far from `1.0` or large RMSE) passed
silently.

**Fix:** `_run_command` return value is now assigned and scanned with two regexes:

- `Scale[:\s]+<value>` — emits `WARNING` if `|scale − 1.0| > 0.10`.
- `RMSE[:\s]+<value>` — emits `WARNING` if `RMSE > 5 × geo_registration_max_error` metres.

Both warnings include the path to `sparse/0_original` so the pre-alignment model can
be recovered or re-used for debugging.
