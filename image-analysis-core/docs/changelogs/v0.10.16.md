# v0.10.16 — Multispectral Bug Fixes: Nodata Consistency and Index Correctness

**Date:** 2026-05-12

Three correctness bugs in the multispectral pipeline, found during code review.

---

## Bug Fixes

### 1. Median composite fallback wrote wrong nodata value

**File:**
`services/orthomosaic_generation/app/core/algorithms/ms_orthorectification.py`

`_median_composite_band` (the fallback path used when `band_manifest` is absent)
called `SetNoDataValue(0.0)` on the output GeoTIFF.  The GPS-guided primary path
uses `_NODATA = -9999.0`.  Any downstream step that read the nodata value from the
file metadata — including `_normalised_difference` in the vegetation index computation
— would treat them as different datasets and fail to mask pixels correctly.

**Fix:** Changed to `SetNoDataValue(_NODATA)` so both code paths write the same
sentinel.  Also applied the DSM coverage mask to the median output (the same
`coverage_mask` clip that the GPS path already applied), so the field boundary is
correct on the fallback path too.

---

### 2. Vegetation index computation did not propagate nodata

**File:**
`services/orthomosaic_generation/app/core/algorithms/vegetation_indices.py`

`_normalised_difference` read both input band arrays and computed
`(a - b) / (a + b)` directly, without first checking which pixels were nodata.
A pixel with value `-9999.0` (nodata) in the NIR band would produce:

```
(-9999 - green) / (-9999 + green)  ≈  1.0
```

— a falsely perfect vegetation score, rendered as bright yellow/green in the
GNDVI/NDVI maps at every nodata pixel (field boundary, shadow, gap).

**Fix:** Before computing the index, the function now reads the nodata value
from each input band's metadata, builds a combined `nodata_mask` (union of
`a == nd_a`, `b == nd_b`, and any non-finite values in either array), computes
the index normally across all pixels, then writes `-9999.0` into all masked
positions.  The output nodata value is set from the same local constant.

---

### 3. DSM coverage mask not applied in median composite fallback

Covered by fix 1 above — the DSM `coverage_mask` is now applied in
`_median_composite_band` using the same `np.where(coverage_mask, median, _NODATA)`
pattern as the GPS composite path, so the field boundary matches the RGB
orthomosaic on both code paths.
