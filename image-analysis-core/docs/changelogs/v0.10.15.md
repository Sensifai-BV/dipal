# v0.10.15 — Multispectral Mosaic: Distance-Weighted Feathering to Fix Band Seams

**Date:** 2026-05-11

Horizontal banding in vegetation-index (GNDVI, NDVI, etc.) and per-band orthomosaics
was caused by `gdal_merge.py` last-writer-wins behaviour exposing bilinear resampling
artifacts at warped image boundaries.  The fix replaces the merge step with in-memory
distance-weighted feathering entirely in NumPy/GDAL Python bindings.

---

## Bug Fixes

### 1. GNDVI / band orthomosaics show hard horizontal seams

**File:**
`services/orthomosaic_generation/app/core/algorithms/ms_orthorectification.py`

**Root cause:**

`_gps_composite_band()` composed a multi-band orthomosaic by calling the external
`gdal_merge.py` utility:

```
gdal_merge.py -n -9999.0 -a_nodata -9999.0 -init -9999.0 <warped_tifs...>
```

`gdal_merge` processes input files in order and writes each image on top of what came
before (**last-writer-wins**).  This means each warped image fully overwrites the
pixels covered by its bounding box.

`gdalwarp` uses bilinear resampling (the default) when reprojecting each image into
the DSM CRS/grid.  At the edge of every source image, bilinear interpolation blends
valid reflectance values with the surrounding nodata region (`-9999`).  A strip of
1–4 corrupted pixels is produced along each image boundary: valid in the
nodata-masked sense (`> -9998`) but radiometrically wrong (blended toward zero
reflectance).

With a 119-image lawnmower flight pattern, `gdal_merge` exposes these fringe strips
as regular horizontal/vertical seams across the entire mosaic — visible as dark or
bright bands every ~20–30 rows in vegetation-index outputs.

Note: DLS radiometric calibration corrects absolute reflectance values (irradiance
variation, solar angle, sensor gain) but does not affect which pixels are selected at
boundaries, so the seams persist regardless of calibration quality.

**Fix:**

Added `_edge_distance_weight(valid)` — a pure NumPy function that computes, for every
pixel, its distance (in pixels) to the nearest edge/invalid pixel using a four-directional
running-reset cumsum trick with no scipy dependency:

```python
def _edge_distance_weight(valid: np.ndarray) -> np.ndarray:
    v = valid.astype(np.int32)
    def _fwd_dist(arr2d):
        cs = np.cumsum(arr2d, axis=1)
        baseline = np.where(arr2d == 0, cs, 0)
        np.maximum.accumulate(baseline, axis=1, out=baseline)
        return (cs - baseline) * arr2d
    left_d  = _fwd_dist(v)
    right_d = _fwd_dist(v[:, ::-1])[:, ::-1]
    top_d   = _fwd_dist(v.T).T
    bot_d   = _fwd_dist(v[::-1].T).T[::-1]
    return np.minimum(np.minimum(left_d, right_d), np.minimum(top_d, bot_d)).astype(np.float32)
```

`_gps_composite_band()` was rewritten to use this weight for blending:

- Allocates `weighted_sum` and `weight_total` float64 arrays matching the DSM grid.
- For each warped TIF: loads the raster band, computes `weight = _edge_distance_weight(valid)`, accumulates:
  ```
  weighted_sum  += data * weight
  weight_total  += weight
  ```
- Final composite: `np.where(weight_total > 0, weighted_sum / weight_total, _NODATA)`

Pixels at the boundary of each source image receive near-zero weight and are
completely overridden by the well-centred pixels of the adjacent strip.  Because
every valid interior pixel contributes proportional to its distance from the nearest
edge, overlapping strips blend smoothly with no hard seam.

The output GeoTIFF is written directly via `gdal.GetDriverByName("GTiff")` using the
DSM spatial reference and geotransform, so the result is geo-aligned to the DSM in
the same way as before.  The external `gdal_merge.py` call is removed.
