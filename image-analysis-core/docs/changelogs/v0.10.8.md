# v0.10.8 — Orthomosaic Failure Reporting & Direct TIFF Band Upload

**Date:** 2026-05-03

Three related fixes that ensure orthomosaic-stage failures are reliably reported
to the backend and band ortho products are uploaded as plain GeoTIFFs instead
of single-file ZIP archives.

Previously, if `run_multispectral_analysis` raised an exception the error
propagated to `BackgroundTaskHandler.run_background_task()`, which updated only
local Redis state to `FAILED` — it never called `_send_orthomosaic_failure_callback`.
The gateway and backend therefore never received a failure notification, so the
job remained in `processing` status indefinitely and the frontend showed no error.

A contributing cause was `_read_dsm_metadata()` in `ms_orthorectification.py`
returning an empty projection string when the DSM was written without a CRS
(because `model_aligner` had not produced `geo_reference.json`).  Passing that
empty string to `gdalwarp -t_srs ""` raised `ValueError: Invalid SRS for -t_srs`
inside `run_multispectral_analysis` — the exact exception that then went
unreported due to the missing try/except.

---

## All Changes

### Bug Fixes

- `fix(orthomosaic)`: Wrap `run_multispectral_analysis` in a try/except block in
  `run_orthomosaic_task()`.  On failure, log the exception, call
  `_send_orthomosaic_failure_callback()` with an error message formatted as
  `"ExcType: message"`, then re-raise — matching the pattern already used for
  `run_pipeline()`.  Closes the silent-failure gap that left backend jobs stuck
  in `processing`.

- `fix(ms_orthorectification)`: `_read_dsm_metadata()` now returns `None` when
  `ds.GetProjection()` yields an empty string or `None` (DSM written without a
  CRS).  The existing guard in `orthorectify_bands()` then raises
  `RuntimeError("Cannot read DSM metadata from <path>")` immediately with a
  clear, actionable log message — instead of propagating an empty string that
  caused `gdalwarp` to crash with `"Invalid SRS for -t_srs"`.

### Refactoring

- `refactor(orthomosaic)`: Remove the `_zip_band_orthos()` helper and all ZIP
  packaging of per-band GeoTIFFs.  Band ortho products (`green_ortho`,
  `red_ortho`, `red_edge_ortho`, `nir_ortho`, `blue_ortho`) are now passed
  directly as TIFF paths in the `outputs` dict.

- `refactor(api_gateway)`: Update the band-product upload loop in
  `_handle_orthomosaic_callback()` to use `{band}_ortho` output keys instead of
  `band_{band}_zip` keys, matching the renamed outputs from the orthomosaic
  service.

### Tests

- `tests(orthomosaic)`: Replace the now-deleted `TestZipBandOrthos` suite (6
  tests for removed code) with `TestRunOrthomosaicTaskFailure` (3 tests):
  - `test_run_pipeline_failure_sends_failure_callback` — `run_pipeline` crash
    triggers failure callback and re-raises.
  - `test_ms_analysis_failure_sends_failure_callback` — `run_multispectral_analysis`
    crash triggers failure callback, does NOT trigger success callback, and
    re-raises.
  - `test_ms_analysis_failure_error_message_includes_exception_type` — error
    message passed to callback is formatted as `"ExcType: message"`.

- `tests(ms_orthorectification)`: Add two tests to `TestReadDsmMetadata`:
  - `test_empty_projection_returns_none` — DSM with `GetProjection()` returning
    `""` causes `_read_dsm_metadata()` to return `None`.
  - `test_none_projection_returns_none` — DSM with `GetProjection()` returning
    `None` causes `_read_dsm_metadata()` to return `None`.
