# v0.9.4 — Fix Calibration Data Not Reaching Orthomosaic

## Summary

Calibration results (multispectral flag, calibration path, band manifest) were never passed to the orthomosaic service due to a wrong lookup key. This prevented vegetation index generation (NDVI, NDRE, GNDVI) even when multispectral data was available.

## All Changes

### Bug Fixes

- `fix(jobs)`: `trigger_next_stage` looked up calibration results with `stage_results.get("calibration")` but the actual key is `"radiometric_calibration"` (matching `ProcessingStage.RADIOMETRIC_CALIBRATION.value`). Fixed in 3 locations: normal trigger, resume path, and reprocess path.

### Infrastructure

- `test(jobs)`: Updated `test_trigger_orthomosaic_with_calibration` test to use correct `"radiometric_calibration"` key in stage_results fixture.

## 🔌 Backend Contract Changelog

No changes.

## 📡 Inter-Service Changelog

| Change | Impact | Action Required |
|--------|--------|-----------------|
| Orthomosaic service now receives `is_multispectral`, `calibration_path`, `band_manifest` from calibration results | Vegetation indices (NDVI, NDRE, GNDVI) will be generated for multispectral datasets in full mode | No action — orthomosaic service already supports these parameters |
