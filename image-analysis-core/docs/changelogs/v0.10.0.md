# v0.10.0 — KPI Metrics Endpoints

## Summary

Rewrites the `GET /metrics/` endpoint to return structured KPI data for CloudWatch dashboard scraping. All counters are now Redis-backed and survive process restarts. Adds per-stage duration tracking, queue wait time measurement, and active job counting. Stage timestamps are recorded automatically during pipeline execution.

## All Changes

### Features

- `feat(metrics)`: Rewrote `GET /metrics/` to return structured KPI JSON:
  - **Uptime**: `uptime_seconds`, `started_at`.
  - **Processing**: `jobs_processed`, `jobs_failed`, `jobs_in_progress`, `average_processing_seconds`, `throughput_per_hour`.
  - **Per-stage durations**: average/total/count for `radiometric_calibration`, `sfm`, `orthomosaic`, `uploading`.
  - **Queue wait time**: average/total/count — measures `created_at` → pipeline start.
- `feat(state)`: Added `stage_timestamps` field to `JobState` model — tracks `started_at`, `completed_at`, `duration_seconds` per stage.
- `feat(state)`: `JobStateManager.start_stage()` now records stage start timestamp automatically.
- `feat(state)`: `JobStateManager.complete_stage()` now records stage completion and computes duration.
- `feat(state)`: New `record_job_metrics()`, `record_queue_wait()`, `get_metrics_summary()`, `count_active_jobs()` methods on `JobStateManager`.
- `feat(metrics)`: All counters now Redis-backed (`photogear:metrics` hash) — survive gateway restarts.
- `feat(jobs)`: `run_pipeline_task()` computes and records queue wait time on pipeline start.
- `feat(metrics)`: New `record_queue_wait()` helper exported from metrics module.

### Infrastructure

- `refactor(state)`: `_record_stage_duration()` uses Redis pipeline (`hincrbyfloat`/`hincrby`) for atomic per-stage aggregation.
- `refactor(metrics)`: `_set_state_manager()` injects `JobStateManager` via DI on first metrics call.
- `feat(metrics)`: `record_job_completion()` / `record_job_failure()` write to both in-memory and Redis.
