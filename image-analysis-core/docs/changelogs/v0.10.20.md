# v0.10.20 — Cross-band strip normalisation (NDVI banding fix), strip-detection robustness, reflectance diagnostics, DSM viewer fixes

## Summary

The recurring diagonal flight-line banding in the NDVI/NDRE/GNDVI maps is fixed
at its root: strip-radiometric gains are now computed **once across all bands**
and applied identically to each image in every band, instead of being computed
independently per band. Per-band gains broke the ratio invariance of normalised-
difference indices — a different multiplicative factor on Red vs NIR changes
`(NIR-Red)/(NIR+Red)` and injected the banding straight into the index. Analysis
of a production output (job `f927f357…`) confirmed the mechanism: the Red and NIR
high-frequency stripe residuals were uncorrelated (r ≈ 0.07), which only happens
when each band is scaled independently — a common per-image illumination factor
would correlate and cancel in the ratio. A latent strip-detection bug (threshold
larger than the inter-strip gap when cross-track GPS jitter was low) was fixed in
the same pass. Reflectance now logs its magnitude and clip rate so the separate
"absolute reflectance ~30× too low" problem can be diagnosed on the next run, and
the DSM visualiser's debug noise / nodata-cliff artifacts were cleaned up.

## Bug Fixes

### fix(orthomosaic): NDVI/NDRE/GNDVI flight-line banding — per-band strip gains broke ratio invariance

**File:** `services/orthomosaic_generation/app/core/algorithms/ms_orthorectification.py`

**Root cause**

`_gps_composite_band` was called once per band and computed its strip-normalisation
gains (`global_median / strip_mean`) **independently for that band**. Because the
Red and NIR per-strip means differ, the per-strip gains differed between bands.
Applying different multiplicative factors to Red and NIR changes the value of
`(NIR - Red) / (NIR + Red)`, so the strip-to-strip illumination steps did not
cancel in NDVI — they were injected into it as banding. Measured on a real output:
Red stripe residual 48 %, NIR 38 %, correlation 0.07 (uncorrelated ⇒ independent
per-band scaling). The RGB ortho, which does not go through per-band reflectance,
showed almost no banding — consistent with a radiometric (not geometric) cause.

**Fix**

- Split the per-band composite into `_warp_band_images` (Pass 1: warp + record
  per-image mean/GPS) and `_blend_band_with_gains` (Pass 2: apply gain + feather).
- `orthorectify_bands` now warps **all** bands first, computes **one shared
  per-image gain** via the new `_compute_shared_strip_gains` (keyed by image stem,
  derived from a band-averaged luminance so no single band dominates), then blends
  every band with that same gain. A common per-image factor now cancels in every
  normalised-difference index.
- `_compute_strip_gains` (per-band) is replaced by `_assign_flight_strips`
  (geometric, band-independent strip assignment) + `_compute_shared_strip_gains`.

### fix(orthomosaic): strip detection collapsed to one strip when cross-track GPS jitter was low

**File:** `services/orthomosaic_generation/app/core/algorithms/ms_orthorectification.py`

**Root cause**

The boundary threshold was `median(gaps > 0.5 m) × 3`. When intra-strip cross-track
jitter was below the 0.5 m filter, the only surviving gaps were the between-strip
ones, so their median × 3 exceeded the actual inter-strip gap and everything
collapsed into a single strip (no normalisation applied at all).

**Fix**

Threshold is now `max(median(all gaps) × 6, 5 m)`. Using the median of *all* gaps
(dominated by the many small within-strip steps) makes the boundary criterion
"much larger than the typical step", robust to both low- and high-jitter datasets.

### fix(visualization): DSM viewer printed debug noise, dropped origin in GDAL path, built false edge cliffs

**File:** `visualization/visualize_dsm.py`

**Root cause / fix**

- Removed stray `print("Load DSM")` / `print("Origin")` / origin debug lines from
  `load_dsm`.
- `origin_x` / `origin_y` were only populated on the rasterio path; added them to
  the GDAL fallback so `meta` is consistent regardless of backend.
- `compute_slope` / `compute_hillshade` filled nodata with the global median,
  creating flat plateaus whose valid/nodata boundaries became vertical cliffs and
  produced spurious ~80-90° slopes and hard shadow lines at every footprint edge.
  Replaced with `_fill_nodata_nearest` (nearest-valid fill via distance-transform
  labels), so boundary gradients are ~0; filled pixels are re-masked to NaN.

## Features

### feat(calibration): log reflectance magnitude and clip rate per band

**File:** `services/radiometric_calibration/app/core/services/base_calibrator.py`

`calculate_reflectance_from_signal` now emits one diagnostic per band via
`_log_reflectance_scale`: reflectance median/p99, the fraction clipped above 1 and
below 0, and the irradiance / exposure / gain values used. These were previously
invisible, which is why the persistent low-absolute-reflectance issue (medians
~0.01 vs the physical ~0.05–0.5) went undiagnosed. This is observability only —
the returned values are unchanged.
